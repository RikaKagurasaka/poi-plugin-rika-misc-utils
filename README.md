# poi-plugin-rika-misc-utils

poi 杂项工具，包含「改造资材统计」和「快捷键」两个标签页。无需新增运行时依赖。

支持 poi 12；不承诺旧版 poi 的兼容性。

## 快捷键

点击输入框录入组合键，设置立即保存在 poi 配置 `plugin.rikaMiscUtils.shortcuts`。
默认不绑定；支持 F1–F24、Ctrl / Alt / Meta 组合键，以及鼠标中键、后退 / 前进侧键（可带修饰键）。在输入框内按鼠标功能键录入，或通过下拉菜单选择。可分别清除，禁止两个操作使用相同按键。

- 刷新游戏网页：调用 poi 的 `gameRefreshPage`。
- 重载游戏框架：调用 poi 的 `gameReload`，仅重载游戏内部框架。

快捷键直接执行，无确认框。键盘默认仅在 poi / 游戏内生效，可开启「键盘全局监听」，设置保存在 `plugin.rikaMiscUtils.globalShortcuts`；开启后其他应用获得焦点时仍可触发。全局键盘使用 Electron `globalShortcut`，注册失败在页面底部显示错误；仅注销本插件注册的按键。在 poi 输入控件中暂停注册，录入时不会触发。

鼠标绑定始终仅在游戏 webContents 内生效，不会全局监听鼠标，不需要原生鼠标依赖。使用 DOM 事件保留中键及前进 / 后退侧键的 button 编号，在游戏各个 frame 捕获可信鼠标事件并阻止匹配按键的默认操作，通过随机标识的 console-message 通知主进程执行固定操作。普通左右键和未绑定按键不受影响。

使用 `@electron/remote` 在主进程同步拦截本地键盘 `before-input-event`，再通知 renderer 调用 poi 原生接口。
插件切换标签页后继续生效，禁用时移除键盘和鼠标监听并释放全局注册，游戏 webview 替换时重新绑定。
重载插件时会重新加载主进程快捷键实现；poi 重设老板键后会恢复本插件的全局注册，冲突时显示错误。初始化失败会清理已创建的监听，可通过页面底部「重新初始化快捷键」重试。

## 改造统计口径

- **已消耗（估算）**：当前所有舰船（含多号机）从改造链初始形态到当前形态的累计成本。每艘船的每个形态最多经过一次。无法还原历史反复转换、已移除舰船、直接取得改造形态等情况。
- **一号机**：每条改造链按改造进度最深、等级最高、取得最早（实例 ID 最小）选择一艘。
- **待消耗**：从一号机当前形态继续，直到终点或下一形态已访问为止。循环链不重复计费，目标形态以纯文本展示。不要求当前达到改造等级。
- **库存**：读取 poi `info.resources`、`info.useitems` 和 `info.equips`。未取得数据显示 `—`，已收到完整道具数据后的缺失项目为 0。poi 道具更新不完整，打开游戏道具栏可刷新；界面提示库存时效。锅炉数包括已装备、锁定、改修装备，不等同于可消耗数量。
- **缺口**：待消耗减库存，最小为 0。

舰船与目标形态自动计算，舰船数据始终从当前 poi store 读取。
不发送游戏请求，也不写入游戏状态。

统计喷火、开发资材、改修资材、设计图、甲板、详报、新型炮熕 / 航空 / 兵装资材、海外舰最新技术、工厂资源及新型高温高压锅炉，不统计弹药和钢材。喷火、开发资材和改修资材使用 poi 原生图标。

消耗明细提供资材下拉单选筛选，默认选择喷火。同时筛选「待消耗明细」和「已消耗明细」：只显示所选资材消耗大于 0 的舰船，并按该项消耗从多到少排列；同消耗按舰船实例 ID 排序。明细仅展示数量，舰船名称与等级 / ID 分两行，目标形态使用纯文本。汇总表始终保留全部统计资材，使用图标的道具仅在悬停时显示名称。统计说明和警告位于页面底部。

## 数据来源与维护

改造链及道具数量使用当前游戏 `api_mst_ship` / `api_mst_shipupgrade`。
按 **改造前 ID + 改造后 ID** 匹配 upgrade 行；不能只按 `api_id` 索引，否则会混淆循环改造。
`api_afterfuel` 实际是钢材，仅作为开发资材规则的计算输入，不纳入消耗统计。

开发资材、喷火、新型炮熕资材、部分改修资材与工厂资源规则来自本仓库已解析的游戏客户端 **6.3.5.0**：

- `ShipUpgradeModelHolder._getRequiredDevkitNum` / `_getRequiredBuildKitNum`
- `ShipUpgradeModel` 的 `newhokohesosizai` / `revkit` / `arsenalmaterial` getter

`data/client-costs.json` 保存源文件 SHA-256 和事实数值表；不执行或打包游戏客户端。
开发资材的默认规则：有设计图且不在例外组（503、504）时为 0；否则按钢材 `<4500 / <5500 / <6500 / >=6500` 对应 `0 / 10 / 15 / 20`。
硬编码规则需要在游戏更新后核对。更新数值表：

```sh
python3 scripts/extract-costs.py <resolved-main.js>
```

该脚本针对 6.3.5.0，更新版本时也需复核默认规则、特殊 getter 和版本号，不能只重跑脚本。
测试夹具从仓库已有 start2 夹具摘取公开舰船字段，无玩家数据。

## 安装和验证

发布到 npm 后，可在 poi 插件管理中搜索 `poi-plugin-rika-misc-utils` 安装。

在 poi 插件设置中用本地目录加载此包，或沿用自定义插件目录的 `npm link` 安装方式，然后启用插件。

```sh
npm run check
npm pack --dry-run
```

实机验收：分别在 poi 和游戏区域取得焦点测试两种快捷键，录入 / 清除 / 重绑后再测试；禁用插件确认按键恢复原行为。
统计页核对多号机选择、循环改造、目标形态、账号切换和游戏道具栏刷新后的库存。

## 发布

初始版本为 `0.1.0`。发版时同步 `package.json.version`、`package-lock.json` 中的版本、`poiPlugin.apiVer` 和 `CHANGELOG.md`。

```sh
npm run release:check
npm publish
```

`prepublishOnly` 会在发布前运行语法检查及插件单元测试。运行发布命令需要 npm 账号具有该包的发布权限，并完成账号要求的认证。
打包白名单仅包含运行时文件、规则数据、README、许可证和更新日志，不包含测试夹具及提取脚本。
全局快捷键、鼠标侧键和真实游戏数据统计的实机验收需在 poi 内完成；打包检查不能替代实机验收。
